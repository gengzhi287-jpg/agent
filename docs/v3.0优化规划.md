# 素材采集 Agent v3.0 优化规划

> 整理日期：2026-09-01 ｜ 定位：Agent 智能体能力深化（区别于 8.31 的工程化优化）
> 原则：不开新坑，把现有项目做到 v3.0；优先「规划能力 + 可观测性」两项。

---

## 一、规划能力升级（P0，核心亮点）

### 1.1 Plan-and-Execute 架构 ✅ 已完成（2026-09-01）
- 现状：单循环决策（模型边看边决定下一步），缺乏整体规划，复杂目标容易漏项或策略混乱。
- 方案：
  - **规划阶段**：接收用户目标后，先让模型输出一份结构化采集计划（JSON：关键词列表、每个的数量/搜索源/尺寸过滤、预期总产出），写入任务状态并展示给用户。
  - **执行阶段**：按计划逐条执行（复用现有 `pipeline.process_keyword`）。
  - **重规划**：某条计划失败或保存数不足时，把当前进展回传给模型，让其修订后续计划（换关键词/换源/调数量），而不是简单重试。
- 改动点：`agent.py` 拆为 `plan()` / `execute()` / `replan()` 三段；`_agent_dispatch` 保留为兼容路径。

### 1.2 反思机制（Reflection）✅ 已完成（与重规划合并实现）
- 现状：每轮工具调用后无自评，靠模型隐式判断。
- 方案：每条计划执行完，插入一次轻量自评调用（或合并进 replan）：「该关键词预期 N 张，实际保存 M 张，失败原因分布是……是否满意？下一步？」，让模型显式输出评估结论，写入 trace。
- 注意：控制调用次数，避免 token 成本翻倍；可与 1.1 的 replan 合并为同一次调用。

## 二、可观测性：Agent Trace（P0，面试分水岭）

### 2.1 决策链路追踪 ✅ 已完成（2026-09-01）
- 方案：新增 `tracer.py`，记录 Agent 每一轮的结构化事件：
  - 时间戳、轮次、类型（plan / tool_call / tool_result / reflection / final）
  - 工具名与参数、结果摘要、耗时、LLM token 用量（usage 字段）
- 存储：`logs/traces/<run_id>.jsonl`，随任务历史关联。

### 2.2 前端可视化 ✅ 已完成（2026-09-01）
- 方案：在现有网页加「决策链路」面板：时间线展示每轮决策（计划 → 调用 → 结果 → 反思），点击展开详情；显示总耗时、总 token、工具调用次数统计。
- 改动点：`/api/status` 返回 trace 摘要；新增 `/api/trace/<run_id>`。

### 2.3 成本看板 ✅ 已完成（2026-09-01，token 维度）
- 方案：按 run 统计 token 用量（prompt/completion 拆分）与 estimated 成本，在历史记录页展示——呼应 2.2 两级过滤的"省钱"叙事。

## 三、评估体系（P1，简历稀缺项）

### 3.1 评测集 ✅ 已完成（2026-09-01）
- 方案：`evals/targets.yaml` 定义 20 个采集目标（含预期：应保存主题、不应出现的主题），`evals/run_eval.py` 批量跑并输出报告。
- 指标：任务成功率、素材命中率（保存图中人工/模型抽检相关比例）、平均耗时、平均 token 成本。

### 3.2 回归对比
- 方案：评测结果按版本存档（`evals/results/`），优化前后对比，支撑简历中「建立 Agent 效果评估体系」的表述。

## 四、工具生态（P2，可选）

### 4.1 MCP Server 化
- 方案：把 `collect_keyword` / `collect_url` / `list_saved` 封装为 MCP Server（`mcp_server.py`，stdio 传输），让 Claude Code / Codex 等 Agent 客户端直接调用采集能力。
- 价值：紧跟 Agent 工具生态，一句话亮点。

### 4.2 记忆升级：用户画像
- 方案：在规则记忆之外，自动归纳用户偏好画像（常用搜索源、尺寸偏好、高频主题），注入规划阶段提示词，让计划更贴合习惯。
